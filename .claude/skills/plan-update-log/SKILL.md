# PlanUpdate 기록 스킬

## 왜 필요한가

이 프로젝트는 여러 에이전트가 병렬로 길게 작업한다. 사용자는 작업 도중 자리를 비울 수 있으므로, 돌아왔을 때 `PlanUpdate.md` 하나만 열면 "누가, 언제, 무엇을, 어디까지" 했는지 전부 파악할 수 있어야 한다. 기록이 빠지면 그 작업은 사용자 입장에서 일어나지 않은 것과 같다.

## 기록 주체와 권한

- `PlanUpdate.md` 파일을 수정할 수 있는 것은 **서기뿐**이다. 두 에이전트가 동시에 한 파일을 쓰면 기록이 유실되기 때문이다.
- 다른 모든 에이전트는 아래 형식의 요약을 만들어 서기(또는 오케스트레이터 경유)에게 **전달**만 한다.

## 기록 시점 3가지

1. **시작**: 작업지시를 받고 실제 작업에 착수할 때
2. **진행**: 계획이 바뀌거나, 단계가 넘어가거나, 문제를 발견했을 때 (단순 반복 작업 중에는 기록하지 않는다 — 소음이 된다)
3. **종료**: 작업을 완료했거나, 오류·한계로 중단할 때

## 기록 형식

항목은 최신이 아래로 가도록 시간순으로 추가(append-only)한다. 기존 기록은 절대 수정·삭제하지 않는다.

```markdown
## [YYYY-MM-DD HH:MM] <에이전트명> — <시작|진행|완료|중단>
- 작업: <무슨 작업인지 한 줄>
- 요약: <핵심 내용 1~3줄. 산출물이 있으면 파일 경로 명시>
- 다음: <이어질 단계 또는 "없음">
```

**예시:**

```markdown
## [2026-08-19 14:20] Developer — 완료
- 작업: fetch_trade.py 1차 구현 (PM 작업지시 WO-1)
- 요약: 연 단위 분할·총계 제거·upsert 구현. src/fetch_trade.py, tests/ 작성. QA 핸드오프 문서 reports/dev_handoff.md
- 다음: QA 검증
```

## 품질 기준

- 요약은 3줄 이내. 상세 내용은 산출물 파일에 쓰고 여기엔 경로만 남긴다.
- "진행 중입니다" 같은 무정보 기록 금지 — 무엇이 바뀌었는지가 없으면 기록하지 않는다.
- 서비스키 등 시크릿은 어떤 경우에도 기록에 포함하지 않는다.
